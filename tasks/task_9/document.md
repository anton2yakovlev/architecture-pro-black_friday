# Настройка чтения с реплик и консистентность

## Таблица операций чтения

| Коллекция | Операция чтения | Источник | Допустимая задержка репликации | Обоснование |
|-----------|----------------|----------|-------------------------------|-------------|
| Products | Проверка остатков товара (stock.quantity) | primary | 0 секунд | Критично для предотвращения продажи недоступного товара. Требуется строгая консистентность. |
| Products | Поиск товаров по категории | secondary | до 5 секунд | Каталог товаров обновляется редко. Небольшая задержка допустима. |
| Products | Получение информации о товаре | secondary | до 5 секунд | Описательная информация меняется редко. Не критично для бизнес-логики. |
| Orders | Текущий статус заказа | primary | 0 секунд | Критично для пользователя видеть актуальный статус. Влияет на бизнес-логику. |
| Orders | История заказов пользователя | secondary | до 5 секунд | Исторические данные не требуют строгой актуальности. |
| Carts | Получение корзины пользователя | primary | 0 секунд | Критично для корректной работы корзины. Пользователь должен видеть актуальное состояние. |

## Допустимая задержка репликации

### Строгая консистентность (0 секунд)
Операции, требующие чтения только с primary:
- Проверка остатков товаров
- Текущий статус заказа
- Получение корзины пользователя

Обоснование: Эти операции критичны для бизнес-логики и предотвращения ошибок (overselling, неактуальный статус заказа, конфликты в корзине).

### Слабая консистентность (до 5 секунд)
Операции, допускающие чтение с secondary:
- Поиск и просмотр товаров
- История заказов пользователя

Обоснование: Данные обновляются нечасто или не критичны для немедленного отображения. Задержка в несколько секунд не влияет на пользовательский опыт.

## Обоснование выбора

### Требования к консистентности данных
Операции с финансовыми последствиями требуют строгой консистентности: проверка остатков предотвращает продажу недоступного товара, статус заказа критичен для пользователя, состояние корзины должно быть актуальным. Операции просмотра допускают слабую консистентность.

### Частота обновлений
Данные с высокой частотой обновлений (остатки товаров, статус заказа, корзина) требуют чтения с primary. Данные с низкой частотой обновлений (каталог товаров, исторические данные) могут читаться с secondary.

### Бизнес-логика
Проверка остатков должна выполняться только с primary для предотвращения overselling. Текущий статус заказа критичен для пользователя. Корзина должна отражать актуальное состояние для предотвращения конфликтов.
